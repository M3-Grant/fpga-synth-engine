# 演奏延迟的测量与上位机演示

> 对应固件：`synth_ttp229`（2026-10-31 起含 `latency_meter.v` + `uart_stream.v`）
> 对应软件：`viz/synth_viz.py`（第 4 面板「演奏延迟」）

---

## 一、为什么要用上位机测，而不是示波器

| | 示波器 | 上位机（本方案） |
|---|---|---|
| 精度 | 取决于时基档位，人工读光标 | **37 ns**（27 MHz 一个时钟周期） |
| 结果 | 一次一个瞬时值 | **几十上百次事件的统计分布** |
| 说服力 | "你看这次是 1.2 ms" | "50 次里最小 1.201、最大 1.312、抖动 111 µs" |
| 成本 | 要示波器 | 零（板子本来就接 USB） |

比赛要求写的是"**≤5 ms 且确定性无抖动**"。**抖动**这个词用示波器是证明不了的，
用直方图一眼就能证明——这是这套方案存在的根本理由。

---

## 二、测的到底是什么（答辩必须讲清楚）

```
        ┌──── 不含 ────┐┌──────────── 本方案测的就是这一段 ────────────┐
手指触碰芯片        TTP229 内部扫描          FPGA 读回 → 消抖 → 音频帧上路
                                      ↑                                  ↑
                                 touch_evt                          frame_tick
```

- **起点** `touch_evt`：FPGA 第一次从 TTP229 读回"某键按下"的那一拍
- **终点** `frame_tick`：消抖后的 note-on 生效之后，**该音符第一个样本真正走上 DIN** 的那一拍

**不含**（这两个量在 FPGA 内部测不出来，只能单独上报或查手册）：

1. TTP229 芯片内部触摸响应时间 —— 无法在 FPGA 侧观察
2. 按键采样间隔的"随机等待" —— 本方案把它单独测出来上报为 `SCAN_PER`
3. DAC / 功放的模拟延迟 —— PCM5102A 数字滤波器群延迟约 0.4 ms（数据手册）

所以界面上除了 `LAT_LAST`，还给了 **`最坏≈` = 采样周期 + 最大延迟**，
这就是"手指落下的时刻最不走运"时的总延迟，也是答辩时最该引用的那个数。

## 三、接线

| FPGA | → | USB-TTL 转接板 |
|---|---|---|
| 引脚 **69**（`uart_txd`） | → | **RXD** |
| GND | → | **GND**（必须共地，否则乱码） |
| — | | TXD 不接（FPGA 只发不收） |

> 电平是 **3.3 V**。5 V 转接板一般能识别 3.3 V 高电平，但不要反过来把 5 V 灌进 FPGA。

插上电脑后，设备管理器里会出现一个新的 COM 口（不是板载那两个 COM7/COM8）。
用串口协议文档最后那个 PowerShell 小脚本扫一下，能收到 `A5 5A` 的就是。

## 四、怎么跑

```powershell
cd D:\Date\DeepseekDate\viz
D:\Tools\Python\python.exe synth_viz.py --port COM9      # 换成实际 COM 号
```

也可以先启动、再在界面上方输入 COM 号点「连接」。

**演示动作**：

1. 手指在触摸键盘上**连按几十下**（同一排键、节奏不必均匀）
2. 盯着「演奏延迟」面板：
   - 左上大数字 = 最近一次的延迟（≤5 ms 绿、5~10 ms 蓝、>10 ms 红）
   - `min / avg / max` = 这一轮统计
   - `抖动` = max − min，**这个数越小越"确定"**
   - `采样周期` = 按键采样间隔
   - `最坏≈` = 采样周期 + 最大延迟
3. 右下直方图：绿柱 ≤5 ms，蓝柱 5~10 ms，红柱 >10 ms，虚线就是 5 ms / 10 ms 门限

## 五、改前 / 改后的预期对比（这段最有说服力）

当前默认参数（**改前基线**）：

| 参数 | 位置 | 值 | 折算 |
|---|---|---|---|
| `TTP_GAP_CNT` | `ttp229_scan.v` / 顶层参数 | 540 000 | **20 ms** 采样间隔 |
| `KEY_CNT_MAX` | `key_scan` 消抖 | 270 000 | **10 ms** 消抖 |

预期界面表现：

- `LAT_LAST` ≈ **10.0 ~ 10.1 ms**（主导项是 10 ms 消抖）
- `采样周期` = **20.0 ms**
- `最坏≈` ≈ **30 ms**
- 直方图会**摊得很开**，红柱（>10 ms）明显 —— 因为 touch_evt 相对 20 ms 扫描周期是随机相位的

**改后**（`TTP_GAP_CNT = 27_000` → 1 ms；`KEY_CNT_MAX = 5_400` → 0.2 ms）：

- `LAT_LAST` ≈ **0.2 ~ 1.2 ms**
- `采样周期` = **1.0 ms**
- `最坏≈` ≈ **1.3 ms**
- 直方图**塌缩成左边一根窄柱**，红柱完全消失

把改前、改后两张截图并排放进 PPT，就是"优化了多少、抖动被消除"的直接证据。

## 六、答辩时可以这样说

> 演奏延迟我们用 FPGA 内部的 27 MHz 计数器直接测量，分辨率 37 ns，
> 统计量通过 UART 实时上传到上位机。
> 实测内部延迟 **X ms**（min Y / max Z，抖动 W µs），
> 按键采样间隔 **1.0 ms**，最坏情况 **不超过 1.3 ms**；
> 加上 PCM5102A 数字滤波器的 0.4 ms 群延迟，**端到端仍远低于 10 ms 要求**。
> 并且延迟是**确定性**的——直方图里所有事件都落在同一格。

## 七、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 界面一直"等待演奏数据…" | 串口没连上，或 FPGA 不在发。先确认 COM 号对不对、GND 有没有接 |
| **板载 COM7/COM8 收不到任何字节** | **实测确认：这块板子的板载调试器 UART 没有接到 FPGA 的 69/70 脚。69 和 70 都试过，两个 COM 口都是 0 字节（FPGA 侧发送指示灯常亮，证明 UART 逻辑在跑）。必须外挂 USB-TTL：引脚 69 → RXD，GND → GND** |
| 收到乱码 / 帧头对不上 | 波特率不是 115200，或没共地，或转接板是 5 V 电平整形过的 |
| 数字一直是 0 / `n=0` | 只按键盘不出声说明触摸没被识别；需要真的**按到键**（按下才会触发 `touch_evt`） |
| `LAT_MIN` 显示成 4294967295 | 这是初始值 0xFFFFFFFF，表示还一次都没测到，按下一次就正常了 |
| 数字很大（>30 ms） | 多半是接错线或按到了红外手势区；也可能是扫描参数被改了 |
| 帧率低 / 卡顿 | 576 字节 × 15 fps = 86 kbps，已接近 115200 上限；可以改成 921600 但要两边同时改 |
