## 二、beta.2 相对 beta.1 的实质变化

### 1. 硬件链路首次打通（10-14）—— 从"仿真通过"到"板上出声"

| 环节 | 结果 |
|---|---|
| USB 枚举失败 | 根因是**数据线**（`VID_0000&PID_0002` / `ProblemCode 43`） |
| 换线后 | `VID_0403&PID_6010` = FTDI FT2232H，**免驱**，COM9/COM10 |
| JTAG | 扫到 `GW2AR-18C` / ID `0x0000081B` |
| 构建流程 | 新增 `code/synth/build.ps1`，**命令行全自动**（不需要打开 Gowin IDE 建工程） |
| 首次上板 | **`tone_test_top` 440 Hz 出声，LED 心跳正常** |

**关键技术坑**（已固化进构建脚本）：
- 引脚 **54/55/56 是 SSPI 专用功能脚**，必须 `set_option -use_sspi_as_gpio 1`，否则 P&R 直接失败
- 命令行工具必须设置 `GOWINHOME` 环境变量

### 2. 音色升级（10-15）

| 项 | beta.1 | beta.2 |
|---|---|---|
| 波形 | 方波（奇次谐波按 1/n 衰减） | **三角波**（按 1/n²，3 次谐波低 9.5 dB） |
| 波形切换 | 无 | **4 种运行时切换**：三角/方波/锯齿/脉冲 |
| 音量档位 | 1/4 满量程（实测刺耳） | **3/16 满量程**（实测定档） |
| 频谱表现 | 能量拖到 10 kHz 以上，10~100 Hz 有 −40~−60 dB 的跳变冲击 | 高频衰减明显加快，低频降到 −70~−90 dB |

**实测依据**：手机频谱 App 对比。三角波不仅削弱了高次谐波，连低频都变干净了 ——
因为**方波每次翻转都是瞬时跳变**，会产生宽频冲击；三角波是连续折线，没有跳变。

### 3. 功放门控降温

| 项 | beta.1 | beta.2 |
|---|---|---|
| `pa_en` | `1'b1` **常开**（静音时功放也全程上电） | 有音符发声立刻开启，**静音 155 ms 后自动关闭** |

保持窗口（155 ms）是为了避免音符间隙反复开关功放产生"啪"声。
**这是针对实测"板子过热"的直接修复。**

### 4. 按键逻辑修复（**队员贡献**）

| 文件 | 问题 | 修复 |
|---|---|---|
| `rtl/key_scan.v` | `press_lat <= key_press` **覆盖赋值**，和弦多拍上报途中若有新键按下，未上报的位被冲掉 → **那个音不响** | 改为"合并 → 上报 → 清除"同拍完成 |
| `constraints/synth_board12.cst` | `key[5]` 分配到**引脚 32**，而 32 **未引出到 40pin 排针** | 改为 **26**（IOB6B / LCD_VS） |
| `sim/tb_key12_notes.v` | 新增 | 精确构造了上述 bug 的时序场景 |

**这两处都经过独立复核**（不是采信自述）：

1. **按键 bug**：用他的测试台分别跑两份代码 —— 我们的版本在检查3 报
   `[FAIL] 音符 7 (G4) note-on 次数 = 0`，他的版本 4 个音全部收到。**bug 真实存在**。
2. **引脚 32**：放大核对 Sipeed 引脚图，左侧排针编号为
   `73 74 75 85 77 15 16 27 28 25 26 29 30 31 17 20 19 18 3V3 GND`，
   右侧为 `5V GND 76 80 42 41 56 54 51 48 55 49 86 79 GND 3V3 72 71 53 52` ——
   **40 个位置里没有 32，而 26 在左侧**。**他的修正正确**。

### 5. 测试体系修正

| 项 | 问题 | 修复 |
|---|---|---|
| `run_sim_all.bat` | **只看退出码** → 把含 2 个 `[FAIL]` 的运行报成 `ALL PASSED` | 新增 `run_sim_all.ps1`，**扫描输出里的 `[FAIL]`** |
| 3 个 tb 的观测窗口 | 只有 5.8~7.8 个音频采样，方波时碰巧能采到峰值，**换三角波后必然漏采** → 假 FAIL | 放宽到 150000 clk（≈2.4 个周期） |
| `tb_synth_board` 的 `pa_en` 检查 | 只测"发声时为 1"，且时机在长时间静音之后 | 改为**双向覆盖**：发声时为 1、静音 208 ms 后为 0 |

修正后实测峰值与理论**完全吻合**：`AMP × 160/255 ÷ 4`
→ AMP=8192 时 `1285`（实测 1283）；AMP=6144 时 `964`（实测 964）。

## 三、架构总览

```
   12× TTP223 触摸键
          │
          ▼
    ┌──────────┐
    │ debounce │ ×12        10 ms 消抖，输出单周期 press 脉冲
    └────┬─────┘
         ▼
    ┌──────────┐
    │ key_scan │            锁存边沿 + 优先编码 + 逐拍上报（每拍一个音符事件）
    └────┬─────┘
         │ note_valid / note_on / note_idx
         ▼
    ┌────────────┐
    │ note_alloc │          声部分配：复用 → 空闲 → 抢占最老
    └─────┬──────┘
          │ voice_busy / voice_note / voice_trig
          ├──────────────────────────┐
          ▼                          ▼
    ┌───────────┐            ┌────────────┐
    │ note_table│ ×VOICE_NUM │   adsr     │ ×VOICE_NUM
    │ 音符→FCW  │            │ A→D→S→R    │
    └─────┬─────┘            └─────┬──────┘
          │ fcw                    │ env
          ▼                        ▼
    ┌───────────────────────────────────┐
    │        oscillator_array           │  generate 例化 N 份
    │  ┌─────────────────────────────┐  │
    │  │ osc_voice                   │  │
    │  │  DDS 相位累加器              │  │
    │  │  wave_sel → 4 种波形         │  │
    │  │  × env 包络调制              │  │
    │  └─────────────────────────────┘  │
    └───────────────┬───────────────────┘
                    ▼
            ┌──────────────┐
            │  mix_tree    │  求和 + 饱和（20 位）
            └──────┬───────┘
                   │ mix_out[17:2]  →  16 位（÷4 留余量）
                   ▼
            ┌──────────────┐
            │   i2s_tx     │  fs = 52734.375 Hz = 27MHz/8/64
            └──────┬───────┘
                   ▼
        板载 MAX98357A（I2S DAC + D 类功放）
                   │  pa_en 门控（有音符才开）
                   ▼
               喇叭
```

|---|---|---|
| `tone_test_top` | 440 Hz 生死线自检 | 不需要（**但会一直响**） |
| `chord_demo_top` | **自动演示**：单音→三和弦→七和弦→音阶，每轮换一种音色 | 不需要 |
| `synth_board_top` | 2 键版（板载按键 87/88） | 不需要 |

## 五、资源占用（`synth_board12_top`，GW2AR-18）

| 资源 | 用量 | 占用率 |
|---|---|---|
| Logic（LUT/ALU） | 2061 / 20736 | **10%** |
| ↳ LUT | 1744 | — |
| ↳ ALU | 317 | — |
| Register | 841 / 15750 | **6%** |
| CLS | 1199 / 10368 | 12% |
| I/O Port | 23 / 66 | 35% |
| DSP（MULT18X18） | 4 / 24 | **9%** |
| BSRAM | 0 | 0% |

**结论：资源极其充裕。** LUT 只用了 10%，DSP 9%，**BSRAM 完全没用**。
这意味着还有很大空间做：
- 提高复音数（4 → 8/16）
- 加混响/延时（正好用 BSRAM）
- 加 wavetable 音色（用 BSRAM 存波形表）
- 第二交互维度

## 八、风险与缺口

按严重程度排序：

| # | 风险 | 严重度 | 说明 |
|---|---|---|---|
| 1 | **第二交互维度完全缺失** | 🔴 **高** | 比赛硬性要求 ≥2 维交互，目前**只有按键这一维**。这是项目最大的缺口 |
| 2 | 12 键版从未上板 | 🟠 中 | 仿真全过，但 TTP223 极性、实际手感、引脚焊接都没验证 |
| 3 | 板子过热后状态未知 | 🟠 中 | `pa_en` 门控已修，但需上板验证是否解决；若 BL616 受损则需换板 |
| 4 | 第二维度硬件未到位 | 🟠 中 | 红外模块情况未知 |
| 5 | `ACTIVE_LOW` 假设未实测 | 🟡 低 | 假设 TTP223 按下为高，若实际相反需改一个参数 |
| 6 | 音色仍偏"电子" | 🟡 低 | 目前是基础波形，缺少包络精修与滤波 |

## 九、下一步建议

**优先级 1 —— 补第二交互维度**（不依赖板子可先做一半）

## 十、beta.2 附带的比特流

发布附件包含已构建的 `synth_board12.fs`（4.41 MB），可直接烧录：

```powershell
$env:GOWINHOME = 'D:\Gowin\Gowin_V1.9.11.03_Education_x64'
& "$env:GOWINHOME\Programmer\bin\programmer_cli.exe" `
    --device GW2AR-18C --operation_index 2 --fsFile synth_board12.fs
```

`operation_index`：**2** = SRAM（掉电即失），**9** = 写外部 Flash（掉电保持）。
