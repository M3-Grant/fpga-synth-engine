### 数学口径的小修正（不影响结论）

发布说明与 `docs/14` 用 `AMP × 160/255 ÷ 4 = 1928` 推峰值。实际链路是：

```
osc_voice 的包络增益 = (env + 1) / 256，env = SUS_LEVEL = 160 → 161/256
三角波折叠后的峰值是 12287，不是 12288（≥16383×12288 >> 14 的截断）
→ 理论峰值 = 12287 × 161 / 256 ÷ 4 = 1931.9，取整 1931
```

实测 1928 略低于 1931，是因为测试台每个采样只取一个点，离散采样没有正好落在三角波顶点上（窗口 150000 clk ≈ 293 个采样，C4 一个周期约 201 个采样）。
**结论不变：+6 dB 精确成立，余量充足。** 已在 `00-先看我.md` 中改写成"理论 ≈ 1931 / 实测 1928"。

## 二、现有 RTL 复审（面向"钢琴谐波"改造）

按优先级排列，**P1 会在本次钢琴改造中一并修掉**。

### P1 · 抢占第 5 个音时没有音头（`note_alloc` + `adsr` 配合缺陷）

`adsr.note_on` 接的是 `voice_trig[g] | voice_busy[g]`。抢占发生时 `voice_busy` 一直是 1，
`voice_trig` 只脉冲 1 拍，所以 `note_on` **没有上升沿** → `trig_edge` 不产生 → 包络不会重新起音。

现象：4 个声部占满后按第 5 个键，音高会立刻变，但包络停在上一个音的状态（可能已经在衰减末端），
听感是"这个音没有音头、发虚"。对钢琴音色尤其致命，因为钢琴最依赖敲击音头。

修法：给 `adsr` 增加独立的 `trig` 端口，直接接 `voice_trig[g]`，不再靠 `note_on` 的边沿。

### P2 · 年龄计数器会溢出（`note_alloc`）

`voice_age` 是 32 位、每个 clk 递增：`2^32 / 27e6 ≈ 159 秒`。
若一个和弦持续按住超过 2 分半，计数器回绕，抢占时"最早分配"的判据失真。
实际演奏概率低，但伴奏持续和弦是真实场景。建议改成"只递增到上限就停"（饱和计数）。

### P3 · `mix_tree` 的求和位宽不随 `VOICE_NUM` 缩放

`SUM_BITS = IN_BITS + 4` 是写死的。当前 `VOICE_NUM=4`、峰值 7727 时最大 30908，20 位装得下（上限 524287）；
但如果以后把复音数改到 8/16，`IN_BITS + 4` 不够，`sum` 会悄悄溢出（饱和逻辑只能兜底，不能救数据）。
建议改成 `SUM_BITS = IN_BITS + $clog2(VOICE_NUM) + 2`。

### P4 · LED 事件指示的展宽时间与注释不符

`evt_stretch` 用 `blink[22:0] == 0` 清除，`2^23 / 27e6 ≈ 0.31 s`，注释写的是 0.2 s。纯文档问题。

### 已确认正常、无需改动的点

- `key_scan` 的"合并 → 上报 → 清除"单 always 结构：和弦丢音问题已修复，逻辑正确
- `pa_en` 门控：`pa_hold` 155 ms 远大于包络 release 的约 1 ms，不会被切断
- `adsr` 的事件锁存（`trig_pending`/`rel_pending`）与 `sample_en` 同拍取旧值的行为正确，最多 1 个采样周期延迟
- `osc_voice` 四种波形均无直流偏置；`AMP` 为编译期常量，乘法被综合成移位加法，不抢 DSP
- `mix_tree` 饱和边界用显式常量（避免早期 `1<<<` 综合出 X 的问题），保持现状

## 三、给队友的修改清单

1. **不要再本地打 tag 后打包上传**。要发布就走：提交 → `git push` → 打 tag → `gh release create`，
   否则别人拿到的"版本号"在仓库里根本不存在。
2. **不要往仓库根塞 zip**。发布包放 Release 附件；仓库只放源码与 prebuilt 码流。
3. 文档随代码一起改。`00-先看我.md` / `README.md` 是评委第一入口，过时的杀伤力比代码 bug 更大
   （第 2 节那张表就是证据）。
4. 打包前跑 `run_sim_all.ps1`（不是 `.bat`）和一次 `build.ps1 -Program none`，并把两者的原始输出贴进发布说明。
5. 若继续调音量，改 `synth_top.v` 的 `mix_out[17:2]` → `[16:1]`（÷4 → ÷2，+6 dB）比继续抬 `AMP` 干净；
   但注意此时 4 声部最坏峰值会到 15448 / 32767（47%），仍安全。
