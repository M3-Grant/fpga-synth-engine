## 四、设计演进：四次改错才定型（重要）

这次 `key_scan` 我改了四版，每一版都踩在**Verilog 的经典陷阱**上。记录下来：

### ❌ 第 1 版：两个 always 块驱动同一组输出

```verilog
// 错误：按下和释放各一个 always 块，都写 note_valid
always @(posedge clk) begin ... note_valid <= 1'b1; ... end   // 按下
always @(posedge clk) begin ... note_valid <= 1'b1; ... end   // 释放
```
**多驱动**，综合会报错或产生不可预期行为。

→ **修正**：合并成单一 always、单一出口。

### ❌ 第 2 版：流式扫描 `key_press`（事件全丢）

```verilog
ST_SCAN_ON: begin
    if (key_press[ptr]) ...    // ← 扫到第 ptr 位时，脉冲早没了
end
```
`key_press` 是 `debounce` 输出的**单周期脉冲**，而扫描要 12 拍才轮到对应位置。

实测证据：
```
t=12  key_press=000000000100   ← 事件脉冲出现
t=13  state=1 ptr=0            ← 状态机才启动
t=15  ptr=2                    ← 扫到 bit2 时，值已是 0
```
→ **修正**：必须先把边沿**锁存成电平**，再逐位处理。

### ❌ 第 3 版：锁存变量的置位与清除分在两个 always 块

```verilog
always @(posedge clk) press_lat <= press_lat | key_press;   // 置位
always @(posedge clk) press_lat[p_idx] <= 1'b0;             // 清除
```
**又是多驱动**——同一个坑踩第二次。

→ **修正**：锁存、上报、清除全部放进同一个 always 块。

### ❌ 第 4 版：给已经是脉冲的信号又锁存一次

```verilog
press_lat <= press_lat | key_press;    // ← key_press 本来就是脉冲，不该再锁存
```
结果 `press_lat` 一直保持置位，**同一个按键被反复上报**（3 键收到 6 个事件）。

→ **修正**：直接用 `key_press` 置位，不要 `|` 累积。

### ✅ 最终版：锁存 + 优先编码 + 逐拍上报清除

```verilog
if (key_press != 0)     press_lat <= key_press;        // 登记新事件
else if (has_press)     press_lat[p_idx] <= 1'b0;      // 上报后清位
if (has_press)          note_valid <= 1'b1; ...        // 逐拍上报
```

## 五、测试平台也踩了两次坑

| # | 现象 | 根因 | 修正 |
|---|---|---|---|
| 1 | 全部检查失败，事件数为 0 | `wait_evt` 任务里"监视超时强制清 key_in"，把自己要等的事件打断了 | 改成"驱动信号 → 跑固定周期 → 核对记录"，不用复杂任务 |
| 2 | 三键收到 6 个事件 | 测试里既让监视块 `on_cnt++`，又在循环里 `on_cnt++`，**同一事件数了两遍** | 用 `snap_on = on_cnt` 做快照差值统计 |

> **教训**：测试失败时先怀疑测试。第 2 次"6 个事件"我一开始以为模块有 bug，
> 用调试 testbench 抓到精确事件流（确实是 3 个）才确认是测试计数错。

## 七、上板说明

### 7.1 引脚约束（⚠ 必须核实）

`constraints/synth_board12.cst` 里 12 个按键引脚是**候选分配**：
```
key[0..7]  → 25,26,27,28,29,30,31,32
key[8..9]  → 41,42
key[10..11]→ 87,88（板载按键，可先用）
```

**必须对照实物/Wiki 核实** 40pin 扩展口的实际引出引脚。
核实方法：Gowin 里导入约束后看 FloorPlanner，报错的引脚换一个候选即可。

### 7.2 接线（TTP223 触摸模块）

| TTP223 引脚 | 接到 |
|---|---|
| VCC | 板卡 3.3V |
| GND | 板卡 GND |
| I/O | 对应的 key 引脚 |
| A/B 焊盘 | **都不焊**（默认高电平有效，匹配代码 `ACTIVE_LOW=0`） |

### 7.3 上板现象

```
led[0] 闪     → 逻辑在跑（最重要判据）
led[1] 亮     → 有音符在发声
led[2] 闪一下 → 收到按键事件
触摸任一键    → 听到对应音高
同时按三键    → 听到和弦（最多 4 音）
```
