## 三、设计决策记录

### 3.1 为什么复音用 `generate` 而不是复制代码

```verilog
generate
    for (i = 0; i < VOICE_NUM; i = i + 1) begin : gen_voice
        osc_voice u_osc (...);
    end
endgenerate
```

**扩复音数只改 `VOICE_NUM` 一个参数**：4 → 8 → 16 → 32 都是一行改动。
这是架构一次做对的意义 —— 如果硬编码 4 个声部，扩到 32 等于重写。

### 3.2 分配策略（优先级）

1. **复用**：该音符已在某声部上 → 复用，不占新声部
2. **空闲**：从 0 号开始找第一个空闲声部
3. **抢占**：全部占满 → 抢占"最早分配"的声部（用 `voice_age` 计数判断）

### 3.3 混音为什么必须做饱和

N 路相加会溢出。若让高位回绕，声音会从最大正数瞬间跳到最大负数，
产生刺耳爆音。`mix_tree` 的做法是超过上限就钳位。

### 3.4 时间参数化设计

| 参数 | 值 | 含义 |
|---|---|---|
| `PHASE_BITS` | 32 | 相位累加器位宽，决定频率分辨率 |
| `BCK_HALF` | 4 | 决定 fs = 52734.375 Hz |
| `AMP` | 0x2000 | 单声部幅度（1/4 满量程，避免刺耳） |
| `VOICE_NUM` | 4 | 复音数 |

## 四、踩过的坑（值得记录）

### 坑 1：`localparam signed` + 移位表达式综合出 X

**现象**：混音输出恒为 X（未定义），整个音频通路失效。

**原因**：`mix_tree.v` 早期版本用
```verilog
localparam signed [SUM_BITS-1:0] MAX_VAL = (1 <<< (OUT_BITS-1)) - 1;
```
iverilog 下这个表达式产生了未定义值，导致所有比较失效。

**修正**：改用显式位宽常量
```verilog
if (sum > 20'sd524287) sat = 20'sd524287;
```

**教训**：饱和边界这类关键常量，**不要用移位表达式，直接写常量**。

### 坑 2：测试平台采样时机错误（两次）

**现象 A**：单音幅度测出 1（期望 2048）

**原因**：`mix_out` 每 **512 个 clk** 才更新一次（音频采样周期），
而测试在每个 clk 都采样，采到的是重复值。

**修正**：必须在 `sample_req` 上升沿采样。

**现象 B**：释放后输出残留 8192

**原因**：`dbg_mix` 是 `mix_out` 再寄存一级，在 `sample_req` 同拍采样
拿到的是**上一周期的值**。

**修正**：`sample_req` 之后再等 1 个 clk 采样。

**教训**：**测一个每 512 周期才更新一次的信号，必须用它的同步信号对齐**，
否则测出来的数字毫无意义。

### 坑 3：测试用例逻辑错误

**现象**：检查"重复按同一音符"时失败，占用 3 个声部（期望 2）

**原因**：测试按的是**已被释放的音符**，此时分配新声部是**正确行为**。
真正该测的是"重复按仍在发声的音符"。

**教训**：测试失败时先怀疑测试，再怀疑代码。

### 坑 4：iverilog 对 ANSI 风格 task 端口支持有限

**现象**：`input cond;`（无位宽）导致 `port already declared` 错误

**修正**：补上位宽 `input [0:0] cond;`，或直接改成内联写法

**教训**：这个项目的测试平台**统一用内联写法**，不用 task/function，
兼容性最好。
