## 一、项目概况

### 1.1 题目要求回顾

| 项 | 要求 |
|---|---|
| 交互 | 自研方案，**至少 2 个独立可控维度**（电容触摸/光电感应/压力检测/无接触手势） |
| 合成 | **完整音频通路全部 FPGA HDL 实现**，逐样本实时运算 |
| 算法 | 波表采样 / 加法合成 / FM 调频 / 物理建模（任选） |
| 延迟 | 控制信号到音频输出 **≤10ms** |
| 复音 | 基础 **≥4** |
| 功能 | 单音实时变调、ADSR 包络、多声部实时混音 |
| I2S | 通过 I2S 输出至 DAC 解码发声 |
| **红线** | **严禁播放预录 PCM、预置推流、整段录音触发** |

### 1.2 核心评分公式

> **吞吐量 = 同时活跃可闻独立振荡器总数 × 实际音频输出采样率**
> （过采样不叠加加分）

**振荡器计数口径**：

| 合成方式 | 计数单位 |
|---|---|
| 波表采样 | 独立相位累加器 + 频率调控 + 包络控制的完整振荡器；**查表不计多谐波，只算 1 个** |
| 加法合成 | 按**运算分量**统计 |
| FM 调频 | 按**调制运算器**统计 |
| 物理建模 | 按并行弦 / 模态单元统计 |

**设计含义**：这是乘法公式，**复音数是分数的核心乘数**。全部技术工作都应服务于"提高能同时发声的振荡器数量"。

### 1.3 评分结构（拓展要求都是加分）

| 类别 | 内容 |
|---|---|
| 基础（必须） | 2 维交互、复音 ≥4、延迟 ≤10ms、ADSR、多声部混音、纯硬件合成 |
| 拓展（加分） | 复音 ≥32 或加法分量 ≥32 路；≥3 维表情；≥2 音色切换；硬件混响/延迟/合唱；延迟 ≤5ms 且无抖动；视听反馈；脱机/智能联动 |

## 二、总体策略

### 2.1 三句话战略

1. **先出声，再谈音质。** 第一天就要让耳机响，避免"写了三周没声音"。
2. **架构一次做对，复音用参数生成。** 从第一版就用 `parameter + generate`，绝不硬编码 4 复音，否则扩到 32 等于重写。
3. **分数靠振荡器数，不靠音质。** 评分是硬指标，把资源花在"多一路声音"上，而不是"更好听"。

### 2.2 功能优先级（决定砍什么）

| 级别 | 内容 | 说明 |
|---|---|---|
| **P0 必须** | I2S 出声、单振荡器、音符映射、2 维交互、复音 ≥4、ADSR、混音 | 不做完拿不到基础分 |
| **P1 争取** | 复音 ≥16、≥2 音色切换、≥3 维表情、硬件延迟/混响 | 直接乘进分数公式 |
| **P2 有余力** | 复音 32、加法合成分量、视听反馈（HDMI 频谱）、机械琴键结构 | 拉开差距 |
| **不做** | 蓝牙/手机 App、在线曲谱、录音回传 | 性价比低、风险高 |

### 2.3 明确不碰的东西

- ❌ 不用软核 CPU（学 C 和 RISC-V 工具链会吃掉全部时间，且纯逻辑更能体现 FPGA 价值）
- ❌ 不做蓝牙、App、云功能
- ❌ 不追求高保真音质、不做过采样
- ❌ 不碰物理建模（难度最高、资源消耗最大）

## 四、技术架构（一次定型的骨架）

### 4.1 模块划分

```
led/按键输入
     │
     ▼
┌──────────────┐
│  交互采集     │  debounce / cap_touch / force_adc
└──────┬───────┘
       ▼
┌──────────────┐
│  音符分配器   │  note_alloc —— note-on/note-off 管理、声部仲裁
└──────┬───────┘
       ▼
┌──────────────────────────────┐
│  振荡器阵列（parameter 复音数）│  osc × N
│  相位累加器 → 波形表 → 包络    │  共享一套波形 ROM
└──────┬───────────────────────┘
       ▼
┌──────────────┐
│  混音器       │  mix_tree —— 流水线加法树 + 饱和处理
└──────┬───────┘
       ▼
┌──────────────┐
│  效果器（可选）│  delay / reverb（用 SDRAM）
└──────┬───────┘
       ▼
┌──────────────┐
│  I2S 发送     │  i2s_tx —— BCK / LRCK / DIN
└──────────────┘
```

### 4.2 关键设计决策（已定，不再摇摆）

| 决策 | 选择 | 理由 |
|---|---|---|
| 时钟架构 | **27MHz 主时钟 + 48kHz 单周期使能** | 绝不用分频时钟驱动逻辑，避免跨时钟域问题 |
| 波形存储 | **共享一套波形 ROM**（多种波形，切换时选表） | 32 个振荡器共用，节省 96% BSRAM |
| 包络实现 | **移位加法近似**，不用 DSP 乘法器 | 48 个 DSP 不够 32 个振荡器各占一个 |
| 复音扩展 | `parameter VOICE_NUM` + `generate` | 4→8→16→32 只改一个数字 |
| 混音 | 流水线加法树 + 饱和处理 | 保证时序收敛，避免溢出失真 |
| 相位位宽 | 32 位累加器，取高 10 位作表地址 | 频率分辨率约 1.1×10⁻⁵ Hz，远超需求 |
| 合成算法 | **波表打底，后期叠加法分量** | 波表最省资源，加法分量可提高计数 |

### 4.3 参数速查

```
采样率 fs      = 48 kHz
主时钟         = 27 MHz
每采样周期时钟数 = 27000000 / 48000 = 562.5 → 取 562 或 563

频率控制字 FCW = f × 2^32 / 48000
  例：A4 = 440Hz → FCW = 440 × 4294967296 / 48000 ≈ 39370534
  例：C4 = 261.63Hz → FCW ≈ 23408735

PWM / I2S
  BCK  = fs × 32 × 2 = 3.072 MHz
  LRCK = fs = 48 kHz
```

## 五、风险与预案

| 风险 | 等级 | 触发信号 | 预案 |
|---|---|---|---|
| **I2S 不出声** | 🔴 | W1 结束仍无声音 | ①检查三线接法与共地 ②用示波器/逻辑分析仪看 BCK/LRCK ③降级：先用 PWM 直推喇叭验证逻辑，再回头调 I2S |
| **DAC 模块不兼容** | 🟠 | 接线正确仍无输出 | 换 UDA1334A；或确认是否需要 MCLK |
| **复音扩不上去** | 🟠 | W5 复音 4 时序不收敛 | 降低采样率到 24kHz；或改用时分复用（TDM）架构 |
| **资源超限** | 🟠 | 综合报资源不足 | 砍包络精度、共享更多逻辑、复音停在 16 |
| **时间不够** | 🔴 | W6 未达复音 8 | 砍 P1/P2，保 P0 完整；**宁可功能少也要稳** |
| **合规性质疑** | 🟠 | 评委怀疑预录音频 | 准备"测试模式"：输出 N 路不同频率，频谱可见 N 个谱峰；RTL 代码可现场指认 |

## 六、合规性自证（必须提前设计，不能等评委来问）

题目明确：现场要"测试模式下输出多路不同频率音频，频谱可观测对应数量独立谱峰，同时可通过 RTL 代码佐证纯硬件实时合成通路，验证无预录音频播放行为"。

**所以从 W5 起就要内置一个测试模式**：

| 模式 | 行为 | 用途 |
|---|---|---|
| 正常演奏模式 | 交互控制发声 | 演示 |
| **测试模式** | 按一个键，输出 N 路等间隔不同频率（N = 当前复音数） | **自证合规**：频谱上应看到 N 个独立谱峰 |

验收标准：N=4 时频谱 4 个峰，N=8 时 8 个峰，N=16 时 16 个峰。

## 七、每周节奏（团队纪律）

1. **周日复盘**：本周产出能不能演示？不能就砍功能。
2. **每天有提交**：代码进版本管理（Git），哪怕只改一行。

5. **不留到最后**：文档、视频、答辩材料从 W6 就开始准备。
