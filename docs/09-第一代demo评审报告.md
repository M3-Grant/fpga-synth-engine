## 二、做得好的地方（值得保持）

| # | 亮点 | 为什么重要 |
|---|---|---|
| 1 | **`i2s_tx` 重写为标准 Philips I2S** | v1 左对齐会让 PCM5102A 左右声道错位、声音发闷。这个修正很关键 |
| 2 | **每声道 32 BCK（非 16）** | v1 只有 16 BCK/声道，采样率被顶到 105kHz。修正后是合理的 52.7kHz |
| 3 | **样本锁存（`l_reg`/`r_reg`）** | 帧起点打一拍，保证发送途中数据不被上游改写。**这是很多人会漏的坑** |
| 4 | **`sample_req` 提前 16 BCK 请求** | 给上游留出计算时间，避免欠载。设计意识很好 |
| 5 | **上电复位（POR）** | `tone_test_top` 用计数器自复位，不依赖按键，减少一类入门坑 |
| 6 | **测试向量覆盖边界值和满量程** | T5/T6 体现了测试思维 |
| 7 | **显式声明 `sample_req` 再使用** | 规避了 iverilog v14 的 "declaration after use" 检查 |
| 8 | **文档记录了踩坑** | `I2S调试记录.md` 对答辩极有价值 |

### 🟠 问题 2：采样率 52734.375 Hz 不是标准音频速率

| 标准速率 | 本项目 | 偏差 |
|---|---|---|
| 44100 | 52734.375 | +19.58% |
| 48000 | 52734.375 | +9.86% |

**影响评估**：
- ✅ **音准没问题**——FCW 按真实 fs 算，A4 实测 440.00 Hz
- ✅ **MAX98357A 支持 8k~96kHz**，能接受这个速率
- ⚠️ **但与标准 48kHz 不兼容**：如果以后要把音频录到电脑分析、或与外设对接，会有问题
- ⚠️ **与 PCM5102A 的隐患**：PCM5102A 通过采样 MCLK 或 BCLK 自动检测速率。52734 Hz 落在它支持的范围内，应该能用，但**换 DAC 后必须重新验证**

**建议**：
- 如果只是"出声"和演示，**保持现状完全没问题**
- 若想更规范，可改 `BCK_HALF`：`5` → 42187.5 Hz，`3` → 70312.5 Hz（但仍非标准）
- **真正的标准 48kHz 需要 24.576MHz 时钟**（27MHz 除不出整数），这就是为什么会有这个偏差——不是设计失误，是时钟源的物理限制

### 🟡 问题 3：MAX98357A 是单声道，注意演示策略

代码注释里已经提到了，这里再强调：

- MAX98357A 是**单声道** D 类功放
- `SD_MODE > 1.4V` 时只输出**左声道**
- 当前 `tone_test_top` 左右声道同数据，所以听不出问题
- **但等你们做复音、立体声效果时，右声道会丢失**

**建议**：
- 频谱验证和最终演示**按计划外接 PCM5102A**（立体声）——你们文档里已经想到了，很好
- 板载 MAX98357A 只当"快速验证出声"用
